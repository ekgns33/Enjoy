# k6로 부하테스트 하기

* 기능구현이 마무리되는 시점에서 부하테스트를 진행하기로 했다.

오늘 해볼 부하테스트 대상은 기록을 조회하는 API이다. 해당 API은 우리 서비스에서 핵심적인 비즈니스 로직이고 range query이기 때문에 좀 더 실전적인 스크립트를 작성할 수 잇을 것 같아서 선택했다.

테스트 환경은 최대한 프로덕션과 비슷하게 하기위해 Docker상에서 CPU 1core, 2GB Mem을 할당하도록 했다. 또한 RDS는 분리되어있기에 컨테이너로 분리했다. 셋업된 환경은 Spring 컨테이너 1개, Mysql 컨테이너 1개이다. 로컬에서 실습하는 경우이므로 k6는 기본 콘솔에서 사용했다.

## 1. k6 설치

https://grafana.com/docs/k6/latest/set-up/install-k6/

k6는 그라파나사에서 만든 경량 테스트 툴로 golang 기반이다. 스크립트는 js로 작성할 수 있어 빠르고 쉽게 시나리오를 구성할 수 있다. 또한 공식문서도 잘 나와있어 원하는 옵션을 찾아서 적용하면 된다!

**Mac OS**

```bash
brew install k6
```

**Ubuntu**

## 2. k6 스크립트 작성

### **a. 테스트 환경 셋업**

여기서 말하는 테스트 환경 셋업은 가상 사용자 수와 테스트 지속 시간, Rampup과 같은 환경변수들이다.



1. **커맨드에서 옵션으로 입력**

```bash
k6 run --vus 10 --duration 30s script.js
```



2. **스크립트에 옵션을 작성**

```javascript
export const options = {  
    vus: 50,  // 가상 사용자 수
    thresholds: {  
        http_req_failed: ['rate<0.01'],   // 테스트 성공 실패에 대한 검증
        http_req_duration: ['p(95)<200'],  
    },  
    stages: [  
        { duration: '10s', target: 50 },  // 스테이지 별 지속시간과 사용자 수
        { duration: '60s', target: 50 },  
        { duration: '30s', target: 50 },  
    ],  
};
```



아무래도 개발자다보니 매번 커맨드 입력보다는 스크립트 파일에 직접 정의하는게 편했다! 옵션에 대해서는 정말 많은 세부사항이 있어서 필요한게 있을때마다 공식문서를 참고하는 중이다. javascript - API 레퍼런스를 제공하고 있다.



문서에서도 옵션을 활성화 하는 방법이 4가지 있다고 한다.

* **CLI에 플래그값 추가**
* **환경 변수**
* **script파일에 options 객체**
* **configuration 파일**

### **b. 요청 시작 전 환경셋업하기**

현재 개발중인 앱서비스는 JWT토큰 기반의 인가처리를 진행하고 있다. 토큰을 얻기 위해서는 로그인을 진행해야하는데, 소셜로그인만을 운영하고 있기때문에 테스트 전용 로그인 API를 사용했다.

* 테스트 시작 전 API를 통해서 테스트 사용자에 대한 액세스 토큰을 발급받는다.

```javascript
export function setup() {

  ... //셋업하는 내용

  const res = http.post(`${BASE_URL}/auth/test/login`, Json.stringify({ user_id : id}));  // 테스트 API 호출

  ...

  // 전역 자료구조에 유저별 토큰 저장
  tokens.push({ 
    user_id: user,
    accessToken: res.json('payload.tokens.access_token'),
    refreshToken: res.json('payload.tokens.refresh_token')
  }); 
}
```

셋업하는 내용은 `setup()` 함수 블록에서 정의한다. default 함수를 실행하기 전 setup을 먼저 실행하게된다.

공식문서에서는 기본적인 k6 스크립트의 흐름을 아래와 같이 설명한다.

{% embed url="https://grafana.com/docs/k6/latest/using-k6/test-lifecycle/" %}

```javascript
// 1. init code

export function setup() {
  // 2. setup code
}

export default function (data) {
  // 3. VU code
}

export function teardown(data) {
  // 4. teardown code
}
```

**default 함수는 각 테스트 iteration에서 k6가 인식하는 엔트리 포인트이다**. 따라서 실제 시나리오 로직을 작성하면된다. VU를 설정하면 각 가상 사용자가 행하는 액션이라고 이해할 수 있다. **또한 setup은 각 가상 사용자마다 정확히 1번만 수행된다.**

* default function으로만 테스트를 수행할 수 있는것은 아니다. 시나리오 함수를 만들고 시나리오를 실행하게 할 수 있다. 공식문서의 예시는 다음과 같다.



```javascript
import http from 'k6/http';
import { sleep } from 'k6';

export const options = {
  scenarios: {
    my_web_test: {
      // the function this scenario will execute
      exec: 'webtest',
      executor: 'constant-vus',
      vus: 50,
      duration: '1m',
    },
  },
};

export function webtest() {
  http.get('https://test.k6.io/contacts.php');
  sleep(Math.random() * 2);
}
```

* `executor` 은 테스트 스크립트를 실행하는 주체인데 종류가 여러가지 있다. 우리는 이 Executor을 여러가지로 변경해서 실제 사용자의 트래픽처럼 환경을 만들 수 있다.\

### c. Executor 종류

**shared-iteration**

* 가상 사용자간 테스트 iteration을 공유한다.
* **각 사용자들에 공평하게 작업을 분배하지 않는다.** Best-Effort로 실행된다.
* 정해진 사용자 수가 있을 때, iteration을 수행하는 데 초점을 맞추는 경우 사용된다. 다시말해 **얼마나 빠르게 예약된 작업을 수행**하는지 궁금한 경우에 쓴다.

**per-vu-iteration**

* 가상 사용자마다 iteration을 설정한다.
* shared-iteration과 반대로 **각각 사용자들이 정해진 양을 수행한다**.

**constant-VUs**

* 고정된 가상 사용자 수로 테스트를 실행한다.
* **최대한 많은 작업**을 수행하도록한다.

**ramping-vus**

* 테스트 스테이지를 수행할때 유저 수를 ramp up한다. Jmeter에서도 ramp up이 있는데 일정 시간동안 서서히 사용자 수를 늘리는 방법이다.

**constant-arrival-rate**

* iteration을 일정한 주기로 수행한다.
* **open-model** executor라고 공식문서에서는 설명한다. 시스템 응답과 관계없이 테스트 iteration을 수행한다.
* system-performance와 상관없이 고정적으로 테스트 iteration을 수행하고 싶을때 사용하라고 한다.

{% hint style="info" %}
**또한 sleep()을 붙이지마라고 문서에 나와있다.**

`arrival-rate executor`에 경우 best-effort로 수행하는게 아니라 정해진 rate와 시간동안 수행되기 때문에 **sleep으로 멈출 필요가 없다.**
{% endhint %}

**ramping-arrival-rate**

* 테스트 수행주기를 점점 늘리거나 줄인다.
* 점진적인 로드에서 사용할 수 있다.
* ramping과정이 추가되었다.

{% embed url="https://grafana.com/docs/k6/latest/using-k6/scenarios/#executors" %}

#### Executor 공식문서 예시

```javascript
import http from 'k6/http';

export const options = {
  scenarios: {
    shared_iter_scenario: {
      executor: 'shared-iterations',
      vus: 10,
      iterations: 100,
      startTime: '0s',
    },
    per_vu_scenario: {
      executor: 'per-vu-iterations',
      vus: 10,
      iterations: 10,
      startTime: '10s',
    },
  },
};

export default function () {
  http.get('https://test.k6.io/');
}
```

공식문서에서 제공하는 예시를 보고 분석해보자.

1번 시나리오는 shared\_iter\_scenario로 여러 **가상사용자가 한번에 로드**되며 100번의 test-iteration을 **최대한 빠르게 소모한다.**

2번 시나리오는 per-vu-iterations로 **10명의 가상사용자가 10번의 test-iteration을 각각** 수행한다.

## k6로 스크립트 작성하고 레코드 조회 API 부하 걸어보기

### **1. init**

```javascript
import http from 'k6/http';  
import { check, sleep, group } from 'k6';  
import { SharedArray } from 'k6/data';  
  
const BASE_URL = 'http://localhost:8080/api/v1';  
const USERS_ID = new SharedArray('users', function () {  
    return Array.from({ length: 50 }, (_, i) => i + 1);  
});

let tokens = [];
```

* import를 하고 BASE\_URL을 지정했다.
* 각 테스트 유저의 PK값을 미리 `SharedContext` 에 할당한다.
  * 테스트 데이터는 미리 세팅해뒀다. 10만건 레코

### **2. options**

```javascript
export const options = {  
    vus: 10,  
    thresholds: {  
        http_req_failed: ['rate<0.01'],  
        http_req_duration: ['p(95)<200'],  
    },  
    stages: [  
        { duration: '10s', target: 10 },  
        { duration: '20s', target: 20 },  
        { duration: '30s', target: 30 },  
        { duration: '40s', target: 40 },  
        { duration: '50s', target: 50 },  
    ],  
};
```

* 스테이지를 5개로 나눠서 테스트를 진행했다.
* 웜엄등을 고려해서 **점점 사용자를 늘리도록** 진행했다.
* 가상 사용자는 10명으로 설정(시작 사용자)
* 테스트 종합결과에서 **실패율이 1%미만, 응답시간의 p(95)가 200ms 미만**일때 성공하도록 작성했다.

### **3. setup**

```javascript
  
export function setup() {  
    for (const user of USERS_ID) {  
        const res = http.post(`${BASE_URL}/auth/test/login`, JSON.stringify({ user_id: user }), {  
            headers: { 'Content-Type': 'application/json' },  
        });  
  
        check(res, {  
            'logged in successfully': (r) => r.status === 200 && r.json('payload.tokens.access_token'),  
        });  
  
        tokens.push({  
            user_id: user,  
            accessToken: res.json('payload.tokens.access_token'),  
            refreshToken: res.json('payload.tokens.refresh_token'),  
        });  
    }  
  
    return { tokens };  
}
```

* 테스트 API로 액세스 토큰을 받아서 저장하고 전역 컨테이너에 담는다.
* 요청시에 액세스토큰을 다시 꺼내서 전송한다.

### **4. default function 테스트 시나리오**

```javascript
export default function (data) {  
	// 1.액세스토큰을 선택한다.
    const vuIndex = (__VU - 1) % data.tokens.length;  
    const user = data.tokens[vuIndex];  
    let accessToken = user.accessToken;  

	// 2. 랜덤한 요청을 위해 정의한 함수들을 사용하여 요청 파라매터를 구성한다.	
    const page = randomIntBetween(0, 5);  
    const size = randomIntBetween(1, 20);  
    let startDate = getRandomDateInPast(30);  
    let endDate = getRandomDateInPast(30);  
    if (startDate > endDate) [startDate, endDate] = [endDate, startDate];  

	// 3. 요청 path를 작성한다.
    const queryString = `?page=${page}&size=${size}&startDate=${formatDate(startDate)}&endDate=${formatDate(endDate)}`;  

    let res;  
    
    // 4. 기록을 조회하는 로직을 작성한다. 액세스토큰이 만료되면 리프레쉬하는 로직도 추가했다.
    group('get records', function () {  
        res = http.get(`${BASE_URL}/records/me${queryString}`, {  
            headers: { Authorization: `Bearer ${accessToken}` },  
        });  
  
        if (res.status === 401) {  
            const newToken = refreshAccessToken(user.refreshToken);  
            if (newToken) {  
                accessToken = newToken;  
                res = http.get(`${BASE_URL}/records/me${queryString}`, {  
                    headers: { Authorization: `Bearer ${newToken}` },  
                });  
            }  
        }  
  
        check(res, {  
            'status is 200': (r) => r.status === 200,  
        });  
  
        if (res.status !== 200) {  
            console.log(`Failed request for user ${user.user_id}:`, res.body);  
        }  
    });  
}

```
