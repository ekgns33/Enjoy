# 분산환경에서 스케줄링 제어 - ShedLo

## 3분산 환경에서 스케줄링을 사용할때 단 하나의 프로세스만 작업을 수행하도록 하는 방법.

### 작업을 스케줄링 하려면?

Spring으로 애플리케이션 서버를 구현하다보면 스케줄링 기능이 필요할 때가 있다. 지연 처리라던가 규칙적인 배치작업을 스케줄링을 통해 구현할 수 있다.

**선택할 수 있는 기술들**

* Java의 ScheduledThreadPool
* Spring Scheduler 추상화

직접 자바로 구현을 할수도 있지만 스프링을 사용하고 있으면 Spring이 제공하는 스케줄링 인터페이스를 사용하는게 편하다.

* 자세한 사용법은 해당 사이트에서 참고할 수 있다.

### 한번만 수행되야하는 작업이라면?

1개의 프로세스만으로 서버를 운용한다면 스케줄링된 작업을 수행하는 주체가 1개뿐이라 상관없다. <mark style="color:red;">**하지만 여러 프로세스가 사용자의 요청을 처리중이라면 어떨까?**</mark>



* 개발자는 서비스 전체에서 1번만 실행되었으면 하는 작업이 각 서버에서 돌아간다.

원치 않은 추가적인 작업이 생길 수 있다. 만약 데이터베이스에서 lock을 잡는 작업이라면 모든 server에서 이를 대기할 수도 있다. 배치성 작업을 배치서버로 분리해도 문제는 해결되지 않는다. 결국 분산 환경에서는 동일하게 문제가 발생하기 때문이다.



이를 해결하기 위해 **공통의 리소스를 활용**하는 방법이 있다. 프로세스들이 공유하는 데이터베이스의 락을 활용하여 1개의 프로세스에서만 작업을 수행하도록 제한할 수 있다. Spring Scheduler와 ShedLock 라이브러리를 활용하면 이를 쉽게 달성할 수 있다. 분산환경에서 프로세스들은 다르지만 동일한 데이터소스를 바라보고 있는 경우에 해당 자원을 사용해서 동시성 제어를 할 수 있다.

{% embed url="https://github.com/lukas-krecan/ShedLock" %}

ShedLock은 분산환경에서 작업이 중복되어 실행되는 것을 방지할 수 있다. 데이터베이스에 ShedLock을 위한 테이블을 만들고 1번만 실행해야하는 작업을 위한 스케줄링 프로세스가 돌때 Lock을 활용하는 것이다.

하지만 ShedLock은 **분산 스케줄러 라이브러리는 아니다.** ShedLock은 언급했듯이 분산환경에서 스케줄링 작업이 1개의 프로세스에서만 돌아야하는 상황을 지원하기 위한 오픈소스다!



어떻게 돌아가는 걸까?

* A, B 서버중 A서버가 먼저 데이터베이스의 테이블 락을 잡는다.
* B 서버는 스케줄링을 위해 테이블 락을 요청한다.
* 이미 A가 락을 잡았기 때문에 **B는 락을 포기한다.**

요렇게 다중 인스턴스에서 **락을 얻지못한 프로세스들은 작업을 포기해버리는 방법으로** 1번의 스케줄링을 보장한다.

### 문제는 없을까?&#x20;

#### 모든 방법에는 장단점이 존재한다. Shed Lock의 장단점은 뭘까

**장점**

* 쉽다. 명확하다.
* 라이브러리로 여러 벤더를 지원한다 (JDBC, Redis, MongoDB...)
* Spring Scheduler와 통합이 쉽다.

**단점**

* **공유하는 데이터 소스가 필요하다**. 락을 잡아야하니까.
* lock **점유 시간 설정에 따라 문제가 발생할 수 있다.**
  * 최대 얼마나 락을 잡을건지? 최대 5분잡았는데 배치가 10분돌면?
  * 요건 비즈니스적으로 파악해야할 수밖에..
*   DB 락을 잡았는데 <mark style="color:red;">**애플리케이션이 죽으면 lock을 release하지 않아서 지연이 생긴다.**</mark>

    * 다시 애플리케이션이 뜰때 lock을 기다리게된다.



실제로 회사에서 배치로 도는 작업이 도중에 서버가 OOM으로 죽은경우가 있었다. 그런데 락을 잡고 놔주질 않아서 새로 실행된 프로세스가 계속 대기하는 장애가 발생한 적이 있다.
