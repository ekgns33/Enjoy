# 동적으로 서버 설정 변경하기 1

### 동적으로 서버 설정 변경?

* 서비스를 운영하다보면 고객 단위가 아니라 시스템 단위로 적용되는 설정 값들이 있다.
  * 예를 들어 메시지 처리의 배압을 조절한다거나..
    * 메시지큐를 소비하는 측에서 쓰로틀링을 할때?
* 카프카를 사용하다보면 `poison pill` 메시지가 등장하는 케이스가 있다. 이런 메시지들은 처리가 불가능해서 서버를 다운시키기도한다. 단순 직렬화 문제라면 재시도 후 DLQ 같은 곳으로 보내도 되겠지만 정상 메시지인데 OOM을 발생시킨다던가.. 이런 메시지들이 발견되면 동적으로 필터링 리스트를 관리하여 처리할 수도 있다. _(정답은 아니고 이렇게도 풀어볼 수 있겠다는 이야기)_



#### Spring 에서 설정값들 어떻게 관리하지?

일반적으로 `application.yaml` 같은 곳에 설정값들을 넣어놓고 스프링 부트가 설정을 해주거나, 프로퍼티들을 커스텀하게 등록하여 사용한다. 보통 저 값들은 static하게 사용한다. 파일에서부터 로드해서 값을 프로세스뜰때 설정해준다.

결국 데이터 원천을 바라보고 로드하는건데, 이걸 그대로 활용하면된다. 우리가 항상 사용하는 전역적인 데이터소스가 있다. 데이터베이스!



#### 데이터 베이스에 동적인 설정값을 저장하고 서버에서 폴링하자.

데이터베이스에 정규화를 할 수도 있고 json 형식으로 넣어놓고 application에서 Map으로 컨버트해서 값을 조절할 수도 있다. _전자는 테이블만봐도 서버의 설정값들을 확인할 수 있는 장점이 있지만 설정값이 추가될때는 테이블 스키마도 변경되어야한다. 후자는 막 가져다 놓고 쓰기 편하다. 대신 테이블만 봐서는 파악이 어렵겠다._



* 폴링은 갱신하는 방법중 하나이다. 만약 설정이 반영될때까지 실시간성이 보장되어야하면 별도 API를 만들어서 갱신을 동기적으로 하도록 할 수도 있다.&#x20;
* 분산 서버라면 모든 서버가 업데이트 해야하는데, 이벤트-기반 시스템이라면 갱신 이벤트를 발행해서 모든 서버가 업데이트를 하도록 할 수도 있을 것 같다.
* 디비가 아니라 메모리를 활용할 수도 있겠다. 근데 이것은 설정 저장소를 어디로 하냐의 차이인듯하다.&#x20;
* central-dogma 기반으로git-based 설정 관리도 할 수 있는 것으로 알고 있다. 요건 한번 사용해보면 재밌을 것 같다.
