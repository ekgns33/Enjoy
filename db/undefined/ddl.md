# 데이터베이스 DDL 알고리즘, 락

데이터베이스 DDL?

* 데이터베이스의 스키마를 변경하거나 추가하는 역할을 하는 언어를 DDL이라고 한다.
* 수정은 DML, 권한 관련은 DCL이라고 한다.



#### 특정 테이블의 스키마를 변경하면?

* 회사에서 사용하는 MySQL 8.0+ 기준으로 보자면..



1. 락을 걸 알고리즘을 정한다.
2. DDL을 실행한다.
3. 메타데이터 업데이트하고 커밋한다.



알고리즘을 정한다는거에서 흠칫할 수 있다. 그런데 MySQL 최근 버전에서는 Instant같은 알고리즘으로 단순 컬럼추가 같은 DDL은 락을 안걸고도 수행할 수 있다. (물론 컬럼 설정값들에 따라서 안될 수도 있음.)

MySQL 공식 문서에서 Online DDL이라는 것을 찾아보면 자세히 나와있다.



#### **메타데이터락**

* MDL\_SHARED\_UPGRADABLE : 읽기/쓰기 가능, 승격 가능
* MDL\_SHARED\_READ : 테이블 읽기 전용 공유락, 락을 얻으면 읽기 가능
* MDL\_SHARED\_NO\_WRITE:  승격이 가능한 읽기 전용 락. 다른 세션의 쓰기를 막음.
* MDL\_EXCLUSIVE : 모든 세션 접근 차단.



이름처럼 점점 락의 수준이 올라가고 제한이 강해진다. READ\_LOCK, WRITE\_LOCK 생각하면 이해 쉬움.&#x20;

* 알고리즘 선택에 따라 lock의 수준이 올라가고 내려간다.
* lock의 수준이 높다면? 당연히 다른 스레드에서는 읽기 조차 불가능하다. 따라서 실 사용중인 서비스에서 DDL을 걸어버리면 요청 스레드는 모두 블로킹된다.
  * _사용자가 있을때 크기가 큰 테이블에 DDL을 걸었다가 요청들이 줄줄이 time-out난 후로는 DDL의 무서움을 알게됐다._
  * 알고리즘 선택도 8.4버전보다 아래라면 직접 지정해줘야한다. 컬럼추가 같은 건 INSTANT 알고리즘을 사용하여 최소 범위로 메타데이터 락을 잡을 수 있다.



#### **알고리즘 선택?**

알고리즘 종류

* COPY
* IN-PLACE
* INSTANT



#### **Copy**

* 제일 오래되고 무식함.
* DDL적용된 새로운 테이블을 만들어서 기존 테이블을 복붙한다.
* 복붙 후에 기존테이블 제거

{% hint style="danger" %}
무조건 COPY쓰는 작업들

* PK drop
* 컬럼 타입 변경
* 문자 char-set 변경
* 스토리지 엔진이 다른거 지원안함.
{% endhint %}

#### In place

* ALTER DDL 수행시점에 다른 세션이 읽기쓰기 모두 가능, 리빌딩도 가능
* 임시테이블을 만들고 복사
* 쓰기작업은 별도 DML 로그에 쌓는다.
* 복사 끝나면 DML로그 적용
* 테이블 이전하고 이전 테이블 삭제



작업에 필요한 공간 확보해야한다. -> 임시테이블 + DML로그 쌓아야함.

그러면 당연히 트래픽이 터질때 하면 DML 로그에 대한 갭이 생길수도 있음.

* 메타데이터락을 2번 잡음.
* 테이블이 크면 오래걸림 -> Copy해야해서.

#### **INSTANT 알고리즘 사용시 메타데이터 락**

* 테이블의 메타데이터를 변경하고 Row Version을 수정하는 방식
  * <mark style="color:red;">**Exclusive Lock을 그래도 사용하긴함.**</mark> 영향 줄 수도 있음.
  * 그래도 테이블 카피를 하진 않으니까 쓰는게 좋음. 빠르다. 좋다.
*   주로 칼럼 추가, 삭제, default, enum 추가 이런거에 씀
