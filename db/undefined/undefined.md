# 테이블 조인 종류

### 조인은 언제 사용하는 걸까?

데이터베이스에 데이터를 정규화하여 저장하고 조회할때 SQL을 사용한다.

* 여러 테이블의 정보를 결합하여 결과를 확인하고싶어요.

이 상황에서 우리는 테이블간 조인(Join)을 사용한다. 그냥 무턱대고 조인! 하면 마법처럼 촤라락 작동하는 것은 아니다.

테이블마다 가진 정보들이 있을텐데 **공통된 정보들을** 통한 연관성으로 테이블들을 연결한다.&#x20;



> 보통 공통된 정보라고 하면 동일한 컬럼의 값이나 키값을 가리킨다.&#x20;

엔티티간 연관을 데이터베이스의 스키마로 모델링할때, 외래 키를 통해 우리는 테이블 간 연관을 명시한다. 외래키를 통해 어떤 테이블이 변경될때, 다른 테이블도 변경되기도 한다.&#x20;



***



### 1. 내부 조인 - Inner join

* **내부 조인 == 교집합**

간단하게 생각하자. 교집합이다. 겹치는 것이 있으면 select하고 없다면 버린다.  두 테이블 모두 존재하는 데이터만 반환하는 조인이다.&#x20;



**두 테이블 모두 존재하는 데이터는 어떻게 정의하나요?**

위에서 테이블마다 가지는 공통된 속성을 기반으로 조인을 수행한다고 했다. **join 대상이 되는 테이블의 특정 칼럼과 현재 select한 테이블에서 지정한 테이블의 특정 칼럼값이 동일한 레코드들만 반환한다.**

예시로 확인해보자\~

| 학번        | 이름 | 성별 |
| --------- | -- | -- |
| 202011288 | 문어 | 남  |
| 202011333 | 호박 | 남  |
| 201912312 | 노루 | 여  |

학생을 표현하는 테이블이 하나 위와 같이 구성되었다고 생각해보자.

학생의 대출 연체기록을 나타내는 테이블이 아래와 같이 있다고 가정한자.

| 학번        | 연체 일자      |
| --------- | ---------- |
| 202011288 | 2024-12-02 |
| 202011333 | 2023-11-11 |
| 203012999 | 2040-12-12 |

우리는 연체 기록이 있는 학생의 학번과 이름, 일자를 알고 싶다. 기준이 되는 테이블은 학생을 의미하는 상단의 테이블이 될것이다.



```
select 학생.학번, 학생.이름, 연체기록.연체 일자
from 학생
join 연체기록
    on 학생.학번 = 연체기록.학번
    
```

요렇게 조인문을 포함하는 쿼리를 작성하게되면 비교대상인 학번을 기준으로 교집합을 만들게 된다.

| 학번        | 이름 | 연체 일자      |
| --------- | -- | ---------- |
| 202011288 | 문어 | 2024-12-02 |
| 202011333 | 호박 | 2023-11-11 |

### 2. 왼쪽 외부 조인 - Left outer join

왼쪽 외부 조인 == 교집합 + 기준테이블(NULL 포함)

* 교집합은 알겠는데 기준테이블이 추가된다고? 이게 무슨 말이지?

집합 기호로 표현하기는 조금 애매하다고 생각이 든다. 교집합이 아닌 친구들은 Join 대상이 되는 테이블의 값들은 NULL로 채워진다. SQL문으로는 `LEFT OUTER JOIN`  또는 `LEFT JOIN` 을 사용한다.&#x20;



| 학번        | 이름 | 연체 일자      |
| --------- | -- | ---------- |
| 202011288 | 문어 | 2024-12-02 |
| 202011333 | 호박 | 2023-11-11 |
| 201012312 | 노루 | NULL       |

조인결과는 다음과 같다. 중요한 부분은 노루가 추가된 점이다. 노루는 **교집합으로 존재하지 않지만 반환 대상에 추가되며, 필드는 NULL로 채워진다.**



***



### 3. 오른쪽 외부 조인 - Right outer join

오른쪽 외부 조인 == 교집합 + 조인 대상 테이블&#x20;

* 스\~\~ 미치겠네. 이게 뭐지?&#x20;

절대 정신을 잃지말자. 왼쪽 외부조인의 정확히 반대행위라고 보자. 조인 조건이 달라도 결과에 들어간다. 물론 일치하지 않는 컬럼들은 NULL로 채워진다. SQL은 `RIGHT OUTER JOIN` 또는 `RIGHT JOIN` 을 사용한다.

| 학번        | 이름   | 연체 일자      |
| --------- | ---- | ---------- |
| 202011288 | 문어   | 2024-12-02 |
| 202011333 | 호박   | 2023-11-11 |
| 203012999 | NULL | 2040-12-12 |

결과는 다음과 같다. 이번에는 학생 테이블에 값이 존재하지 않지만 연체 기록에는 존재하기 때문에 이름이 NULL로 표현되었다.

* 오른쪽 외부조인은 거의 사용해보지 않았다. 순서를 바꾸면 오른쪽 외부조인이 왼쪽 외부 조인이 되기 때문이다.

초등학교 컴퓨터실에서부터 나는 엑셀을 왼쪽 위부터 오른쪽 아래로 읽게끔 프로그래밍이 되었다 ㅋㅋㅋ. 어떤식으로 작성해도 상관 없지만 내가 작성한 쿼리문을 누군가 확인해야한다면, 사람들이 이해하기 편하게 정책을 정하는게 어떨까?&#x20;



***



### 4. 교차 조인 - Cross join

교차 조인 == 카티시안 곱

* 카티시안 곱이란 뭘까? 넌 누구냐..

위키백과에서는 카티시안 곱을 이렇게 설명한다.

> [수학](https://en.wikipedia.org/wiki/Mathematics) , 특히 [집합 이론](https://en.wikipedia.org/wiki/Set_theory) 에서 두 [집합 ](https://en.wikipedia.org/wiki/Set_\(mathematics\))A 와 B 의 데카르트 곱은 _A_ × _B_ 로 표시되며 a가 A 에 속 하고 b가 B 에 속하는 모든 [순서쌍 ](https://en.wikipedia.org/wiki/Ordered_pair)( _a_ , _b_ ) 의 집합입니다 .



학교 수업시간에 배운 것 같은데.. 두 집합의 원소들로 만들 수 있느 모든 순서쌍의 집합; 모든 경우의 수라고 보면 된다! 데이터 베이스의 관점에서 보면, 조인 대상이 되는 테이블과 기준 테이블간의 모든 조합을 만들어 반환하는 것이다.&#x20;

```
select 학생.학번, 학생.이름, 연체기록.학번, 연체기록.연체일자
from 학생
cross join 연체기록
```

이렇게 쿼리를 작성하면 아래와 같은 결과가 나온다.



| 학번        | 이름 | 성별 | 학번        | 연체일자       |
| --------- | -- | -- | --------- | ---------- |
| 202011288 | 문어 | 남  | 202011288 | 2024-12-02 |
| 202011333 | 호박 | 남  | 202011288 | 2024-12-02 |
| 201912312 | 노루 | 여  | 202011288 | 2024-12-02 |
| 202011288 | 문어 | 남  | 202011333 | 2023-11-11 |
| 202011333 | 호박 | 남  | 202011333 | 2023-11-11 |
| 201912312 | 노루 | 여  | 202011333 | 2023-11-11 |
| 202011288 | 문어 | 남  | 203012999 | 2040-12-12 |
| 202011333 | 호박 | 남  | 203012999 | 2040-12-12 |
| 201912312 | 노루 | 여  | 203012999 | 2040-12-12 |

3 X 3 = 9. 총 9가지의 경우수가 출력된다.



**주의할 점**

모든 경우의 수를 반환한다니... 무섭지 않은가? $$O(n^2)$$ 의 시간과 공간이 아득해진다... 리소스를 많이 잡아먹는 만큼 주의해서 사용해야한다. 실제 가지고 있는 데이터에 비해 무지막지한 양이 출력되기 때문이다.

***

### 5. 자연 조인 - Natural join

자연 조인 == 겹치는 컬럼이 있으면 내부조인 / 없으면 교차 조인

&#x20;inner join을 할때는 어떤 컬럼을 대상으로 조인을 선언하고 그 대상 컬럼의 값을 가지고 비교했다. 자연조인에서는 조인 조건절을 따로 적지 않아도 자동으로 조인을 수행해준다. 따라서 공통으로 존재하는 컬럼이 있을 때는 결과가 내부조인(inner-join)과 동일하게 출력된다.&#x20;

#### :thinking: **그런데 없는경우는?**

* <mark style="color:red;">**자연 조인은 공통된 컬럼이 없으면 교차조인이 수행된다.**</mark>

호락호락한 친구는 아니었다. 이런 함정이 숨겨져 있다니. 상황에 따라 출력값이 달라지는 조인이라고 이해하고 사용은 자제하자. 명시적으로 내부조인이나 크로스 조인을 직접 선언하자.
