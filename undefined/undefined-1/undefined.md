# 카프카 컨슈머를 위한 신뢰성 내용

#### 7.5.1 신뢰성 처리를 위한 컨슈머 설정 (p196)

4가지 속성

* **group.id**&#x20;
  * 같은 그룹 id의 컨슈머 여러개가 동일한 토픽을 구독하면 해당 토픽 전체 파티션의 부분 집합이 할당된다.
  * 각 컨슈머는 다른 내용을 처리함.
* **auto.offset.reset**
  * 커밋된 오프셋이 없거나 컨슈머가 브로커에 없는 오프셋을 요청하는 경우
  *   <mark style="color:purple;">`earliest`</mark> → 맨 처음부터 읽는다

      &#x20; → 디스크 IO 터질 수 있음.

      &#x20; → 중복 처리가 발생함.
  * <mark style="color:purple;">`latest`</mark> → 중복 처리는 해결되지만 유실될 수 있음.
* **enable.auto.commit**
  * 컨슈머가 알아서 커밋하는 설정.
  * 메시지 중복 처리를 제어할 수 없음. → 자동으로 커밋하니까.
  * **메시지를 가져와서 일부는 커밋하고 일부는 처리하지 않은 시점에 컨슈머가 멈추면 중복 처리하게됨.**
*   **auto.commit.interval.ms**

    * 오프셋을 자동으로 커밋하면 커밋 주기를 결정한다.
    * 줄이면 중복 처리는 줄어들지만 부하가 생김
    * 높이면 중복 처리는 생기지만 부하가 줄어듦

    &#x20;  → 트레이드 오프

#### 7.5.2 명시적으로 오프셋 커밋 (p197)

**메시지 처리 → 오프셋 커밋, 상태 처리 X**

* 상태 처리가 필요없으면 그냥 메시지를 처리하고 커밋하면 그만
  * 자동 커밋 or 폴링 주기 마지막에 커밋

{% hint style="danger" %}
**커밋 빈도는 \[성능]과 \[크래시 발생시 중복 처리] 사이의 트레이드 오프**&#x20;

* **메세지마다 커밋하는 방식은 메시지가 매우 낮은 빈도로 들어올 때나** 사용할 수 있다.
* 커밋은 상당한 성능 오버헤드가 필요하다.
  * **각자 사용처에 맞게 균형을 잡아야한다.**
* 루프 안에서 여러번 커밋, 루프마다 커밋…&#x20;
{% endhint %}

**폴링 루프 중간에 커밋하는 경우**

* <mark style="color:purple;">**마지막으로 처리된 메시지의 오프셋**</mark>을 커밋해야한다.
* 마지막으로 읽어온 메시지의 오프셋이 아니다.

{% hint style="danger" %}
**리밸런싱**

* 리밸런싱을 염두에 두고 설계해야한다.
*   할당된 파티션이 해제되기 전에 오프셋을 커밋

    → 새로운 파티션이 할당 됐을때 애플리케이션의 상태를 지워야함.\</aside>
{% endhint %}

**컨슈머는 재시도를 해야 할 수도 있다.**

* poll을 호출하고 레코드가 처리되지 않아 나중에 처리해야할 수 있음.
*   레코드 30번을 처리 실패한 상태에서 31번을 커밋하면 안됨.

    → 31번까지 커밋한거로 표시됨.

**\[해결 방법]**

1. **재시도 가능한 에러가 발생한 경우에는&#x20;**<mark style="color:purple;">**마지막으로 처리에 성공한**</mark>**&#x20;레코드의 오프셋을 커밋**
   * 나중에 처리할 레코드를 버퍼에 저장하고 pause를 호출해 레코드 처리를 계속한다.
2.  <mark style="color:purple;">**새로운 토픽**</mark>**에 쓰고 계속 진행해버린다.**

    * 별도의 컨슈머 그룹이 재시도 토픽의 레코드를 처리한다.
    * DLQ와 비슷한 구조



**컨슈머가 상태를 유지해야 할 수 있다.**

* poll 메서드 호출 사이에 상태를 유지해야 할 수도 있음.
*   예를들어 ‘이동 평균’을 구한다

    * 재시작 했을때 마지막 오프셋부터 처리하는게 아니라 그 이전의 상태값을 복원해야함.
    * 그래야 정확한 평균을 구할 수 있으니까.

    **→ 이럴때는 마지막으로 누적된 값을 오프셋 커밋할때 `‘results’` 토픽에 쓰는것**

    → 스레드가 시작될때, 작업 중단 시점 + 마지막으로 누적된 값을 가져올 수 있다.
